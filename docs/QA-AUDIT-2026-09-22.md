## Outstanding findings

### High: cloud API authorization is incomplete

`proxy.ts:15` bypasses its authentication gate for cloud deployments. `app/api/system/recovery/route.ts:43` reads a caller-supplied `x-user-role`; its condition also permits a missing role. Consequently this code does not establish an authenticated administrator before recovery operations. A server-verified staff session and authorization policy are needed across protected APIs. A client role header is not a trustworthy authorization boundary. This finding is from source inspection; destructive cloud probes were not performed.

### Medium: mobile horizontal overflow

At 390px viewport width, the document measured 395px wide. The main form was readable, but responsive layout does not fully pass. Several header items extend beyond the viewport inside scrolling navigation; the precise source of the extra document width remains unresolved.

### Test-isolation incident and data-review limitation

The first test run used the pre-existing recovery test, which operated on actual workspace storage: it incremented the revision, created backups, restored a just-created snapshot, and applied retention. The pre-existing master audit and shipment-document tests also used application storage rather than isolated fixtures. These tests have now been isolated.

Post-run snapshots parsed and the 55-account invariance check passed. This establishes structural/accounting consistency, not byte-for-byte preservation. No pre-run file hashes were captured, so record-level changes and retention effects cannot be ruled out. Test identifiers remain in the shipment-document snapshot; their original creation time was not established. No business records or backups were deleted manually to hide or undo these effects.
